# JAO Code Quality Audit

Ponytail-style static review, 2026-10-28. Expected load: multiple staff or service processes and concurrent applicant submissions; actual traffic was not measured. These are source-backed improvements only. No code, tests, dependencies, or database records were changed by this audit. Security findings and their approval needs are in `SECURITY_AUDIT.md`.

## Must fix

1. **Submission code drops the only answers it was given** (`app/Http/Controllers/ApplicationSubmissionController.php:48-60`). It maps an empty array and returns success; a real submission cannot preserve responses. Use the request's validated answers and keep the existing transaction, with ownership/type checks from SEC-04 and SEC-05. This is a correctness and data-loss fix, not a reason to add a service layer.
2. **Version numbers are calculated per template but unique for the whole table** (`app/Http/Controllers/FormVersionController.php:36-50`; `database/migrations/2026_08_27_084606_create_form_versions_table.php:19`). Two templates both attempt version `1`; the second can hit a uniqueness error. Choose one numbering rule and align controller, schema, and tests. Any schema correction needs separate approval.

## Should fix

3. **Create and update field rules disagree** (`app/Http/Requests/CreateFormFieldRequest.php:26-33`; `app/Http/Requests/UpdateFormFieldRequest.php:26-33`). For example, create limits `type` to 50 characters while update allows 100; create permits a one-character `default_value` while update requires at least three characters. A client can create a value it cannot later save unchanged. Align the existing request rules; avoid a new validation framework.
4. **Section reordering is less safe than the adjacent field reorders** (`app/Http/Controllers/FormSectionController.php:41-64`; `app/Actions/FormField/ReorderFormFields.php:20-57`). Section moves update several rows without a transaction or a lower bound on position, while the field action uses a transaction and the field endpoint requires `min:1`. A failed or concurrent move can leave ordering inconsistent. Apply the same bounded, transactional pattern; no new abstraction is needed unless shared behavior is actually extracted.
5. **Creating a field loads the entire section** (`app/Http/Controllers/FormFieldController.php:31-34`). `$formSection->formFields->max()` hydrates all fields to find the last position, while the sibling section and option controllers use a database `max()` query. Use the existing query pattern to avoid work proportional to section size. Confirm expected concurrency separately before adding locks.
6. **The critical submission path has no direct feature test** (`app/Http/Controllers/ApplicationSubmissionController.php:32-64`; `tests/Feature/ApiRoutingTest.php:59-60`). The discovered tests check the route name, API-key middleware, and other controllers, but none submits answers and checks the stored application, field ownership, and token reuse. Add one focused end-to-end test per distinct security decision when implementation is approved; this audit cannot run database tests.

## Nice to have

7. **Unregistered scaffolds and duplicate token checks increase review surface** (`app/Http/Controllers/SubmissionFileController.php:8-48`; `app/Http/Controllers/ApplicationInvitationController.php:32-46`; `app/Http/Middleware/ValidateApplicationInvitation.php:17-30`; `routes/api.php:20-66`). The upload controller has empty methods, the invitation `checkToken()` method is not routed, and the token middleware is aliased but not attached to the invitation routes. Confirm product intent, then remove unused scaffolds or reuse one correct token policy. Do not remove a necessary future security control merely to reduce lines.
8. **Invitation expiry mixes a date column with timestamp comparisons** (`database/migrations/2026_08_27_094451_create_application_invitations_table.php:21`; `app/Http/Controllers/ApplicationInvitationController.php:22`; `app/Http/Controllers/ApplicationFormController.php:22`; `app/Http/Controllers/ApplicationSubmissionController.php:37`). A seven-day timestamp is stored in a date column, then compared with `now()`. Depending on the database, an invitation may expire at the start of its final date. Decide whether expiry is a date or an instant and make storage and checks agree; a column change needs separate approval.

No unnecessary service-class layer was found: the two action classes contain multirow reorder transactions and have callers. No dependency removal is recommended from source evidence alone. No line-count or performance gain is claimed without a measured baseline. No active route performs file upload, so upload safety needs review before that scaffold is ever routed.
